# typeAutogen

Schema-driven code generator for OA C++ types (enums, structs). Stdlib Python only — no pip deps, runs anywhere with Python 3.11+.

## Status

**Type generator** — generates enums and structs from TOML schemas under `tools/typeAutogen/schema/`.

Each schema emits:
  - `.gen.h` header-complete enums, conversions, and POD structs
  - `.gen.cpp` include anchors reserved for future non-header generated code

## Usage

```bash
# Generate all schemas to tools/typeAutogen/output/
python3 tools/typeAutogen/oatypeautogen.py

# Dry run — print what would be written
python3 tools/typeAutogen/oatypeautogen.py --dry-run

# Write generated files into source/
python3 tools/typeAutogen/oatypeautogen.py --live

# Generate specific schema
python3 tools/typeAutogen/oatypeautogen.py \
    --schema tools/typeAutogen/schema/core/coreTypes.toml
```

## Layout

  - `schema/<domain>/*.toml` — source of truth, one file per domain
  - `oatypeautogen.py` — CLI entrypoint and code emitters
  - `oatypeautogen_lib/` — config, schema validation, emitters
  - `output/` — checked-in generated review fixtures mirroring `source/`
  - `README.md` — this file

## File Structure

Generated files follow the `oa::FnMatrix` pattern:
  - `source/cpp/include/oa/<domain>/type.gen.h` — generated public definitions
  - `source/cpp/lib/oa/<domain>/type.gen.cpp` — generated include anchor
  - `source/cpp/include/oa/<domain>/type.h` — public non-generated header that includes `type.gen.h`

Enum conversions are inline and header-complete; a public type never depends on
whether its generated `.cpp` anchor is compiled. Do not add a second `Type.gen.h`
under `lib/`: `source/cpp/lib` is an include root for the `oa` library, so a
duplicate would shadow the schema-generated public header for library sources.

Runtime routing is the deliberate exception: `runtimeTypes.toml` emits
`source/cpp/lib/oa/runtime/type.gen.h`. Kernel family, route, and storage-plan
identities are serialized implementation details, not installed SDK types.

## Schema Format

```toml
# tools/typeAutogen/schema/core/coreTypes.toml
domain = "core"
namespace = "oa"

[[enums]]
name = "ScalarType"
underlying_type = "U8"
generate_tostring = true
generate_fromstring = true
values = [
    { name = "Float32", value = 0, serialized_name = "float32", comment = "32-bit float" },
    { name = "BFloat16", value = 1, comment = "Brain float 16" },
    { name = "Float16", value = 2, comment = "Half precision" },
    # ...
]

[[structs]]
name = "PrecisionConfig"
fields = [
    { name = "mode", type = "Precision", default = "Precision::FP32" },
    { name = "determinism", type = "DeterminismMode", default = "DeterminismMode::Stable" },
]
```

`serialized_name` is optional. It keeps a stable wire/file spelling independent
of the C++ enum identifier; when omitted, the identifier is used.

## Generated Output

**Public generated header (`source/cpp/include/oa/core/type.gen.h`):**
```cpp
// AUTO-GENERATED by tools/typeAutogen/oatypeautogen.py — DO NOT EDIT.
#pragma once
#include <oa/core/types.h>

namespace oa {

enum class ScalarType : U8 {
    Float32 = 0,  // 32-bit float
    BFloat16 = 1,  // Brain float 16
    // ...
};
[[nodiscard]] constexpr const char* scalarTypeToString(
    ScalarType inType) noexcept {
    // generated switch
}
[[nodiscard]] inline ScalarType scalarTypeFromString(
    const char* inString) noexcept {
    // generated null-safe comparisons
}

} // namespace oa
```

**Public header (`source/cpp/include/oa/core/type.h`):**
```cpp
// OA Core Types
#pragma once
#include <oa/core/type.gen.h>
```

**Include anchor (`source/cpp/lib/oa/core/type.gen.cpp`):**
```cpp
// AUTO-GENERATED by tools/typeAutogen/oatypeautogen.py — DO NOT EDIT.
#include <oa/core/type.gen.h>
```

## Adding a New Type

1. Add `[[enums]]` or `[[structs]]` entry to the appropriate domain's TOML schema
2. Run the generator: `python3 tools/typeAutogen/oatypeautogen.py --live`
3. Add a consumer test for the public value or conversion contract

## Domain Split

Types are organized by domain to enable modular builds:
  - **Core**: Foundational types (oa::ScalarType, oa::Precision, oa::DeterminismMode)
  - **Ml**: ML layer types (oa::Activation, oa::UpsampleMode)
  - **Vision**: Image/video types (oa::PixelFormat, oa::VideoCodec, oa::BorderMode)
  - **Ui**: viewer navigation mode
  - **Runtime (private)**: GEMM route-cache identities (oa::GemmKernel,
    oa::StoragePrecision)

Audio and Render gain schemas only when a complete consumer-tested vertical
slice needs generated values; configured output paths alone are not a shipped
type surface.

This enables building subsets like:
  - Core + Runtime (minimal compute)
  - Core + Ml (ML only)
  - Core + Vision (vision only)
  - All (full stack)

## Unified Generator

Use `tools/oaautogen.py` to run all generators at once:

```bash
# Generate all (types + functions)
python3 tools/oaautogen.py

# Generate types only
python3 tools/oaautogen.py --types

# Generate functions only
python3 tools/oaautogen.py --functions

# Write to source/
python3 tools/oaautogen.py --live
```
